# AI Workforce — foundation and limitations

This is an incremental foundation, **not a production-ready enterprise AI workforce**. Existing NAi functionality remains, but its legacy inventory, projects, conversations, activity and settings are globally scoped and must not be treated as company-isolated. Do not store cross-company sensitive information in those areas until application-wide isolation and a security review are complete.

## Available today

* A global NAi administrator can create a workforce company and becomes a manager. Only explicitly added company members can access that company's workforce dashboard, assignments, work items and events. A global admin does not automatically get access to companies they are not a member of. A global admin who is a company manager can add/remove members; at least one manager must remain. Global `viewer` users cannot write even if assigned a higher company role.
* Operations is the **only implemented agent/tool**. A company operator or manager submits a natural-language request. An OpenAI model proposes (but does not execute) a single internal work item, or returns unsupported. A company manager reviews the proposed text and explicitly approves or rejects. Only approval creates a real company-scoped database record; its ID is shown. Operators can mark that work item complete. This does not create a legacy project task or write to an external application.
* Permission checks are reapplied for the requester before planning, after the model response, and when a manager approves. Approved execution and event records are committed in one database transaction. The assignment-to-work-item unique constraint prevents duplicate creation. Assignments, proposal, result and work item content are encrypted at rest using Laravel's APP_KEY. Keep APP_KEY backed up securely; changing it makes encrypted data unreadable.
* A failed or unsupported assignment can be retried explicitly as a **new** assignment. Each retry can be billed. Job errors never fabricate a result. Automatic recovery of an abruptly killed, stuck `planning` job is not implemented; investigate worker failure before taking administrative action.
* Company-scoped events record submissions, planning, decisions, execution and work-item completion, without storing the prompt in the event. Events are operational database records, not tamper-proof audit logs. The screen reports known status counts and provider-reported successful-plan token usage; it does not calculate cost or account for all failed calls.

## Configuration and operation

1. Use PHP 8.3+ and a backed-up MySQL/MariaDB database. On upgrades, preserve `.env`, APP_KEY, the database and storage; deploy the code and run `php artisan migrate --force` and `php artisan optimize:clear` using the correct PHP binary. The direct web installer is only for fresh installs. See `INSTALL-CPANEL.md` for deployment details.
2. Set `WORKFORCE_OPENAI_API_KEY` and optionally `WORKFORCE_OPENAI_MODEL` on the server in `.env` (not in chat), then run `php artisan config:clear`. This key is separate from the existing NAi Engine UI setting. OpenAI account/model access and billing are required. The workforce planner currently has one provider implementation behind a PHP interface; adding another requires backend code, not just changing a setting.
3. Configure cron to run `php artisan schedule:run` every minute. The scheduler runs a dedicated `workforce` database queue worker every minute. Alternatively use `php artisan queue:work database --queue=workforce --timeout=75 --tries=1` under a process supervisor and avoid running competing scheduler workers. Ensure PHP process-control support and hosting time limits are suitable; database queue `retry_after` must exceed the 75-second worker timeout. Worker operation and supervision must be verified on the host. Stuck jobs or scheduler lock failures require operator investigation.
4. In **AI Workforce**, create a company, add members, and submit a request. A manager approves only after inspecting the complete proposal. Planning sends the instruction to OpenAI; do not submit secrets or sensitive data without company approval. No legacy inventory or company records are sent by this planner.

## Not yet implemented

Multi-agent delegation, dependency management, HR/finance/sales/customer-service and other specialised agent backends, document uploads and search, department and agent-specific grants, source citations, payment/journal/contract/termination operations, external integrations, executive reports, cost estimation, tamper-resistant audit and company isolation across legacy NAi. No access to Nowills applications is assumed. No payments, external messages, financial postings, destructive actions or other high-impact tools exist in this module; do not infer that approval UI alone makes them safe. Further phases require real integration contracts, least-privilege permission design, adversarial testing and operational/security review before production use.
